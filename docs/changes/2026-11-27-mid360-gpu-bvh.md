# Mid-360 GPU BVH 候选

`Start-Simulator.ps1 -GpuLidar` 为启用 Mid-360 的专用 MuJoCo 会话选择 GPU。双哨兵采用 1× 扫描密度。显式 `-CpuLidar` 保留双哨兵 Chaos 0.25×，`-LidarRayScale` 可对两条路径覆盖采样密度。当前默认仍为 CPU。

GPU 路径对已经启用查询且阻挡 RMSimLidar 的 Chaos 烹焙碰撞几何建树。场地使用静态分桶 SAH BVH，车辆连杆使用按 BodySetup 和材质配置复用的局部 BVH。每个 MuJoCo 历史快照以相同的连杆身份组装动态实例 BVH。当前场景实测包含 18 个静态组件、90 个动态组件、33 份局部几何，合计约 507 万个基元。未知碰撞形状在显式 GPU 模式下报错，并保留 Chaos 入口。

两路射线共用一次 HLSL dispatch。轮廓查询优先按普通玻璃层数在一次遍历中收集自车透明面，密集玻璃和邻接遮挡回到原有的逐层距离推进及 16 次查询上限，同样在一个着色器线程完成。独立硬件光追开关与主视角、双相机、视觉阈值无代码改动。

渲染线程用四槽 `FRHIGPUBufferReadback` 回读，游戏线程按提交顺序交付。对象销毁、连接变化及物理世代变化通过提交批次的身份检查处理。GPU 决定首个碰撞几何，CPU 用其原始双精度平面复算命中距离。测量仍沿用原 5 μs 时钟、同一 MuJoCo 位姿插值、扫描模式、NIR、噪声和 ROS 二进制封包。后台按脉冲编号预计算同一公式的方向和噪声。预计算未就绪时沿用即时计算。

## Windows DX12 实测

`tools/unreal/Build-ImportLab.ps1 -EngineRoot E:/simulator-tools/UE_5.8` 构建成功。现有协议、LiDAR 和 Mid-360 合计 35 项单测通过。

RTX 5080 Laptop 和 2560×1440 渲染视口，100% RenderScale、TSR、NoLumen，两路真实桥接传输。以下是同配置 13 秒短测，客户端直接读取生产桥协议。GameThread、RenderThread、GPU 整帧为 UE 时间计数的样本中位数。双雷达 CPU 每帧为 5 秒区间内两路发射与处理的总墙钟时间除以同区间的世界更新数，未计入实例建树和提交，因此是下界。

满速两路各收到 118 个完整扫描窗，`DroppedScans`、`IncompleteScanDrops`、`MissingPoseRays` 均为零。实际载荷逐槽验证 5 μs 时间和四通道顺序。GPU dispatch 的分窗均值为 0.381–0.405 ms，最高单次 0.895 ms。初版 GPU 满速每帧 CPU 耗时下界约 1.25 ms。

移动状态下，两路各 8,192 条 MID-360 发射对拍无命中分歧或材质判定差异，最大法线角误差 0.00044°。静态场地的最大位置偏差约 0.000286 cm，超过 0.0001 cm 严格上限。补充对拍每路 450 条车辆几何射线，其中 75 个自车命中和 371 个其他车辆命中。该组没有几何分类或光学分歧，位置误差小于 0.000020 cm。

两名慢读客户端均触发 `slow_reader` 并重连。重连后继续按 10 Hz 仿真时钟收到完整扫描，慢读试验中的丢弃计数记录在原始摘要。满速试验与移动重连试验均正常关闭，退出时仍有回读批次待回收。复位探针观察到蓝方桥 epoch 0 → 1，重连之后未检出跨 epoch 乱序。实际双 ROS 2 导航和视觉都启动，1440p 观测约 81.44 Draw FPS，RTF 0.9996，并正常关闭。单独使用 UE 随附 DXC 编译了 DXIL 和 Vulkan SPIR-V，布局步长符合 GPU 结构声明。Windows DX12 记录保存在 `artifacts/verification/mid360-gpu-bvh-20261127/`，包含三组 JSON、CSV、失败对拍及 UE 日志。

逐帧 0.5 ms、静态平面精度及 Ubuntu Vulkan 原生验收仍未达到默认切换条件。场馆外围非均匀缩放碰撞墙出现最大偏差。单精度缩放复算的试验未达门限，留下失败数据并移除该试验实现。设备底层的真实发射图样与光机参数的实机标定沿用原项目的验证边界。
