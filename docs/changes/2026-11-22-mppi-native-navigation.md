# RMUC 原生 MPPI 接入与回头弯复测

使用 ROS 2 Humble 与 Nav2 1.1.20 的 Windows 原生二进制。测试启动器单独加载经过哈希检查的两个 MPPI DLL 及包索引。两次初始启动因包索引在原生环境初始化时丢失而失败。测试启动器在原生工作区激活后追加包索引，修复后实际配置并运行 MPPI 与五个评分插件。

现全向控制器可在同一局部代价地图中调用 MPPI 预测平移。输入由估计底盘速度转换至固定导航系，底盘旋转仍交由原小陀螺控制。MPPI 提议继续经过当前路径速度、车体限值、整车扫掠和制动检查。对照候选在受限时还对原跟踪方向执行同一套弯道预判及整车停止检查，采用可验证的前进速度更高的指令。

Windows 同组跨场从 (7.86, −6.78) 到 (−8.32, 6.16)，启动时实测已启用 2 rad/s 小陀螺，保留轮地接触与实时避障。短程测试墙钟 3.24 秒，终点误差 0.126 米，524 个位置零静态重叠。

直接采用 MPPI 候选方向的全程在左回头弯超时取消。该弯 MPPI 建议速度中位数 3.810 m/s，估计实际速度中位数 0.084 m/s。日志记录 1215 次指令制动限速。独立补评覆盖已走过的 4,809 个车身位置，静态重叠零处。平台专项 1,845 个位置无静态重叠。

比较两种方向的候选完成了动作，墙钟 46.48 秒，物理时间 48.06 秒，终点误差 0.196 米，4,636 个位置无静态重叠。记录了 13 次选择原跟踪方向的限频日志。波浪路、平台和出口专项 1,519 个位置无静态重叠。当前超出 26 秒且墙钟差仍需缩小，未应用到默认配置。

MPPI 在短时窗内采样可行控制序列并按路径进度、对齐和避障代价排序，每个周期采用第一步。Humble 的标准全向模型主要将采样速度直接作为下一步速度，尚需模拟舵轮的加速度和转向响应才能让预估轨迹贴近实体。 [Nav2 MPPI Humble 包文档](https://index.ros.org/p/nav2_mppi_controller/)

## 舵轮响应模型复测

将独立编译的舵轮响应模型用于 MPPI 候选预测。模型从估计车速初始化，使用 AIM 车包里的加速、制动、转向和速度变化率限制。已有真实底盘和安全制动仍在原链路，候选仿真模型独立运行。用例覆盖起步加速、侧向转弯和倒车前停车。 原生短程墙钟 3.14 秒，物理 3.91 秒，356 个位置、0 处静态重叠。 完整跨场墙钟 59.16 秒，物理 61.90 秒，6,102 个位置、0 处静态重叠。 三段平台专项通过，1,451 个位置、0 处静态重叠。 本次同时调整了采样数，试跑结果无法单独归因于响应模型。

在整个速度区间都比较两种方向的试验用时 48.16 秒，物理时间 50.75 秒，4,733 个位置无静态重叠。相较仅在低速受限时比较，整车制动扫掠触发从 59 增至 95 次。已恢复低速比较版本。
