## 运行边界和复现

红蓝各装置状态随现有裁判 JSON 输出，`field_devices` 记录网格绑定、装甲防护、旋转、灯位、小组进度、机会、闸门和检测窗口。到时优先比较控制度，再比较有效攻击伤害和总剩余血量。F6 从结束态进入新回合时会一并清空旧回合状态。

`tools/unreal/Prepare-RmucRune.ps1` 从已获授权的源 GLB 离线拆分并导入转子，`-DartOnly`、`-OutpostsOnly` 和 `-VisibilityOnly` 分别准备闸门、前哨及固定查询网格。中央平台保留原始碰撞，裁判射线改用剔除静止转子面的同源固定网格和实际转子查询面。车辆接触仍由绑定 SHA 的原 MuJoCo 静态场地求解。源模型和生成的大型 UE 内容留在本机。

Windows UE5 原生构建与三组 C++17 独立回归通过。以 AIM Sentry 在完整 RMUC 地图离屏启动，三类分件均绑定成功，前哨速率达到 `2.513274 rad/s`，双闸门都在 +30 秒获得首次机会。最终构建启用 `-RefereeFieldDeviceSelfTest`，能量机关与前哨装甲在两个角度的 32 次原生射线检查全部通过。固定平台命中保留，原静止装甲面不再遮挡动态检测。最终记录目录 `artifacts/maps/rmuc2027/field-native-check-20261124T085605Z`，UE 模块 SHA-256 `224d739d05e87860f855617b7478f07e0b4ee9ace843561b4438d3c82e1437a5`。
