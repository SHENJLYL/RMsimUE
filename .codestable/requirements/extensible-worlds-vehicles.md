# 地图与车辆扩展

## 用户故事

- 作为测试者，我希望换用其他地图继续运行现有机器人程序。
- 作为新车型开发者，我希望导入机器人描述后获得明确的可用能力与缺失配置提示。
- 作为比赛环境维护者，我希望地图和车辆版本可追踪，失败时能知道具体哪项不兼容。

## 为什么需要

每次换地图或车辆都修改仿真核心会增加维护成本，也容易使碰撞、坐标和比赛区域与画面不一致。

## 怎么解决

把车辆和场地作为有版本的资源包检查和加载。导入时检查结构、单位、引用与能力，缺少关键属性时明确报错。

## 边界

- 即插即用指已支持的车辆能力与资产格式；不承诺任意 URDF、任意传动机构无需适配。
- 首个切片只处理车辆包 v1 和受限 URDF，不包含 UE 运行时网格导入。
- 地图视觉、碰撞、定位地图和战术区域必须一致；代码许可与资产授权分别核验。

## 已实现子集与当前样例

- 2026-11-13：车辆包 v1 离线校验、受限 URDF 解析、两种样例与规范化导出已通过 Windows 验收（26项测试24通过、2项权限跳过）。完整需求仍为 draft。
- 用户将第一运行样例指定为现有AIM哨兵手动控制；已导出独立FBX/PBR并保留原模型。2026-11-15已实际运行，见后续验证记录。

- 2026-11-15：现有AIM手动visual rig在Windows UE5.8.4实际运行；导入/尺寸核验、18操控与9碰撞检查通过。完整地图、通用车型物理和双平台需求仍未完成。
- 2026-11-15：两张平地box地图与占用/区域接口已运行。用户指定RMUC2027为第一地图后，接入DJI来源静态mesh场地及WT CDK地形裁剪，支持有界坡地试驾。未完成比赛规则、任意车型动力学与坡地定位闭环。当前先Windows，Ubuntu做离线适配。
- 2026-11-15：AIM接触车辆子集已在Windows原生通过红蓝波浪路高低速往返与操控/射击/墙体检查。11部件和独立凸碰撞有哈希绑定，Windows/Linux离线重建共用脚本。完整需求仍为draft：独立舵向、实车惯量/摩擦标定、任意车型和Ubuntu运行仍未验收。
- 2026-11-16：独立舵向已实现为15部件/13刚体，车辆包drive-profile直接驱动配置和控制响应。普通/小陀螺镜头相对移动、坡向抓地和45项原生检查通过；本机LK解算适配及其配置预备件已落地。实车标定、任意车型完整适配、全ROS节点和Ubuntu原生仍待完成。
